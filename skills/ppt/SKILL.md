# PPT 汇报技能 (Build My PPT)

制作严谨、清晰、充实且文字自然的演示文稿。偏向学术或技术汇报语调、克制蓝色视觉体系、紧凑的流程说明、强有力的进展与难点分析、默认隐私合规保护，以及可靠的 Windows 交付兼容性。

当需要读取、生成或修改 `.pptx` 或 `.potx` 文件时，请与 Codex 内置的 `pptx` 技能配合使用。遵循 `pptx` 技能进行底层文件操作与渲染；将本技能作为叙事逻辑、文本表达、视觉风格、信息密度和最终效果的权威指导。

## 查阅设计规范

在规划或编辑页面前，先阅读 [references/styleguide.md](references/styleguide.md)。按需应用相关章节，不加载无关的项目内容。

切勿捆绑或预设任何特定机构的标志、名称、模板、项目实例、学科细节或机密品牌资产。将所有私有资产与可识别内容隔离在可复用技能包之外。

## 默认隐私与匿名化保护

- 将所有用户提供的文件与提取的数据视为私有、仅限当前任务的输入。
- 仅检查用户明确提供或指定的任务范围文件。不得扫描相邻文件夹、以往任务目录、云存储、消息或无关的工作区内容。
- 优先使用本地计算。除非用户明确要求特定外部服务与范围，否则不得将素材源文件、提取文本、截图或生成产物上传、传输、检索或发送至外部服务。
- 机构、公司、院校、院系、专业、团队、实验室、项目、产品、系统、客户及个人身份信息默认保持匿名。在非必要时使用中性角色标签（如 `组织`、`团队`、`任务`、`系统` 或 `模块`）。
- 材料中出现标识符仅作为私有上下文，不得视为公开许可。用户要求使用、总结或检查材料，并不代表同意保留其身份标识。
- 起草前，在内存中将所有带有身份特征的名称和特定描述符整理为“禁止输出清单”。不要保存或展示该清单。在标题、封面字段、正文、备注、媒体、文件名、链接及元数据中保持一致替换。
- 不得从文件名、目录名、Logo、水印、文档元数据、截图、以往任务或风格样例中推测或披露身份。仅在用户明确指示在最终文稿中保留或显示该确切标识时方可保留。指令模棱两可时，一律脱敏匿名化。
- 剔除不必要的个人数据、联系方式、账号名、工号/学号、内部 URL、仓库路径、设备标识、精确地点以及可能识别来源的日期。仅保留准确传达工作内容所需的最小事实。
- 切勿将私有内容、摘录、截图、Logo、模板或元数据复制到本技能目录或其他可复用参考文件中。临时提取文件存放在特定任务工作目录中，交付成功且不再需要时及时清理。
- 不得在幻灯片、演讲者备注、导出文件或最终回复中暴露源文件名、绝对路径、隐藏元数据或内部草稿规划文本。

## 冲突决策优先级

遇到冲突时按以下顺序裁定：

1. 遵循用户当前的明确指令。
2. 执行上述隐私保护规则，除非用户明确要求面向特定受众展示具体标识。
3. 遵循当前演示文稿的官方模板或品牌指南。
4. 将用户亲自编辑并指定的最新文稿作为最强的风格参考。
5. 应用本技能的默认规范。
6. 应用通用的演示文稿常规做法。

尊重用户的刻意修改。切勿仅仅因为早期版本使用过，就盲目还原旧的措辞、颜色、版式或页数。

## 构思先于排版（叙事结构）

1. 仅检查用户明确提供或指定的文档、图片、视频、表格及既有幻灯片。
2. 仅提炼文稿所需的汇报目标、受众、汇报场合、时间限制、当前结论、论据支撑、未决难点及期望决策；剔除身份标识。
3. 先在内部确定文稿的总体逻辑主线。常见的技术或研究进展汇报叙事流为：
   - **极简封面**：标题、报告属性、时期或版本；除明确要求外，其余身份匿名。
   - **总体结论与核心指标**：用一页点明核心进展、当前所处阶段及核心突破。
   - **流程或链路压缩**：最多一页，仅交代完成任务所必需的系统/实验拓扑，不长篇大论。
   - **核心进展与能力证明**：重点篇幅，展示阶段性产出、功能实现、实测数据、对比图表、实物或界面实据。
   - **问题复盘与难点分析**：重点篇幅，明确指出未完成项、性能瓶颈、鲁棒性不足或卡点，不粉饰太平。
   - **下一步计划与排期**：明确行动项、责任角色、时间节点与验收指标。
   - **极简封底**：简练结束语，如“汇报完毕 敬请指正”。
4. 控制总页数：日常技术与学术汇报通常控制在 5-10 页内，聚焦信息增量与核心问题，坚决摒弃套话填充页。
5. 遵循 [references/styleguide.md](references/styleguide.md) 中的版式模式与测定参数。根据材料灵活调整，不强行将所有文稿塞进完全相同的流程中。

## 坚决杜绝 AI 感、机械感与需求复述

- **严禁直接搬运用户需求长句**：绝不机械地把用户的提示词或需求原话直接复制为幻灯片标题、副标题或大纲（例如用户输入“帮我把这篇关于目标检测进展的材料整理成PPT”，严禁把封面或正文标题写成“关于目标检测进展的材料整理”或“目标检测进展汇报材料”），必须提炼出具体、明确、可量化的核心结论。
- **坚决剔除 AI 八股空话**：坚决删除“全方位赋能”、“多维度协同”、“在这个数字化飞速发展的时代”、“助力迈向新台阶”等假大空套话；全篇以技术指标、参数变化、实测现象、版本号与工程事实说话。
- **杜绝流水账与制作元说明**：不写“接下来我们来看流程”、“根据上述材料进行分析”等无价值的过渡性废话；幻灯片中严禁残留“AI 辅助生成”、“制作建议”等任何元信息。
- **保持自然真实的人类表达**：行文遵循专业学术与一线工程汇报习惯，简短有力，主谓宾结构清晰，杜绝生硬机翻口吻。

## 真实表达进度

直接使用准确的状态文本。标准状态词汇定义如下：

- `已完成`：所指功能或模块已开发完成，并经过独立验证。
- `进行中`：正在进行联调、联合测试或处于活跃推进中。
- `待提高`：功能已实现，但在性能、一致性、准确率或可靠性上仍显不足，需要持续打磨。
- `未完成`：规划的开发或端到端重复验证尚未落实。

切勿使用多种刺眼的彩虹色彩表示状态。主要通过措辞、实心与空心、边框粗细以及克制的重点强调来区分状态。

## 安全处理图像与视频

- 仅在任务许可范围内检查媒体素材。
- 选用图片必须能有力证明某个阶段、功能、结果或问题。
- 保持克制裁剪，确保核心对象、界面状态或实验现象清晰易懂。
- 使用前对非必要的姓名、人脸、工牌、账号、联系方式、二维码、序列号、内部路径、窗口标题等可能泄露身份的图层进行遮挡或涂抹。
- 仅在图片含义不明时添加简明图注。
- 优先选用具有代表性的静态截图，以保证 Windows 平台的可靠显示。
- 导出媒体时去除 EXIF 等图片元数据。仅在明确要求时嵌入视频，并附带脱敏后的封面图或静态后备方案。
- 除非用户明确要求，否则不要在幻灯片中展示源文件名、素材来源或路径标签。

## 严谨编辑既有演示文稿

1. 始终基于副本操作。先提取可见文本，仅在编辑或隐私审查需要时检查备注、批注、隐藏页和嵌入对象。
2. 在修改前完整渲染每一页幻灯片，从全局把控文稿基调。
3. 识别用户相较于早期版本做出的改动（若有）。
4. 继承用户已调优的措辞、视觉层级、配图选择及间距。
5. 保留源文件中的私有隐藏内容，但在交付的副本中予以剔除，除非当前请求明确要求保留。
6. 仅修改用户要求的范围，并做必要的排版一致性与隐私修正。
7. 若改动了全局主题或母版，重新复查受影响的每一页。

绝不用旧版生成内容覆盖用户亲自修改过的最终文稿。

## 交付前全方位质量验证

交付前逐项落实检查清单：

1. **确认叙事**：无多余的背景套话页、无凭空虚构的完成项、未遗漏关键难点与后续行动。
2. **确认文本**：自然流畅的中文表达、结论前置的主标题、不留任何制作痕迹或元评论、不陷入无关的技术细枝末节。
3. **确认视觉**：克制蓝色系配色、清晰视觉层级、均衡信息密度、对齐工整、无低幼化装饰性图形、品牌标识处理规范。
4. **确认可读性**：无文字截断、无重叠遮挡、无字号过小标签、无突兀换行、图片未遮盖重要信息。
5. **确认隐私**：将文稿内所有文本与媒体同内存中的“禁止输出清单”对比，确认无未授权的机构、专业、项目、客户、团队或个人标识残留在可见正文、配图、备注、批注、替代文本、文件名或链接中。
6. **检查包结构**：检查 PPTX 压缩包内的备注、批注、隐藏页、自定义 XML、嵌入/链接对象、外部关系、文档属性、缩略图和媒体元数据，清理交付副本中的敏感信息。
7. **元数据清理**：清理 PPTX 和导出的 PDF 元数据（如作者、公司、主管、最后编辑者、标题、主题、关键字、来源路径及工具临时名称）。
8. **全文二次比对**：提取最终 PPTX 与 PDF 的所有可见文本与隐藏文本，查漏补缺，排除残留标识。
9. **结构校验**：校验 PPTX 结构包完整性。
10. **平台兼容转换**：在重视 Windows 兼容性时，使用 LibreOffice 进行重新保存或转换，并再次执行隐私扫描（避免格式转换重写元数据）。
11. **PDF 渲染核对**：导出 PDF 并渲染所有页面进行视觉复核。
12. **总览与局部细审**：检查全局缩略图以评估整体节奏，并在全尺寸下细审高密度信息页与含图页面。
13. **终验闭环**：完成兼容性保存后再次打开产物，复验确保没有悬空外部链接或残留的私有临时文件。

若文稿需在 Windows 上下载，默认采用 ASCII 安全的文件名基名。条件允许时同时交付 `.pptx` 与 `.pdf`。

## 清洁交付

仅汇报最终输出文件的基名或工作区相对路径、总页数及已完成的验证步骤。切勿暴露绝对路径、原始素材文件名或无关目录。只说明确实存在的关键局限性。不要流水账般叙述每一步制作过程，也无需附带技能的通用说明。
