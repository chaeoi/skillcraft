# 通用技术文档与工程规范深度撰写指南

本指南系统性总结面向高规格工程技术规范、系统架构方案、算法原理解析、接口契约说明与技术报告等**所有文档类工作**的通用文字叙述手法与结构准则。

无论文档载体采用 Word (`.docx`)、Markdown (`.md`)、PDF、在线协作 Wiki 还是代码仓库内的架构说明，其核心叙事逻辑、文字严谨性与因果推导均强制遵循本规范。

---

## 一、 通用文字叙述手法：彻底杜绝 AI 感与套话

### 1. 禁用表达与反面模式（负面清单）
- **严禁机械复述用户需求**：杜绝“正如您所提到的…”、“我理解您的目标是…”、“好的，下面我将按照要求为您编写…”等无价值废话。开篇第一句直接切入核心技术方案或系统架构。
- **杜绝 AI 八股与机械腔**：
  - 严禁空洞的升华修辞：“具有划时代意义”、“显著提高了系统的智能化水平”、“具有广阔的应用前景”、“众所周知”、“显而易见”。
  - 严禁机械的连接词滥用：“综上所述”、“总而言之”、“不可否认的是”。
- **杜绝未经验证的绝对化断言**：严禁在未给出数据支撑时断言“彻底消除了误差”、“实现了绝对零延迟”。应基于客观事实表述为“将控制偏差收敛至预设门限 $\pm \delta$ 以内”、“动态补偿了通信与执行滞后 $\tau$”。

### 2. 倡导的高级人类工程文风
- **直入主题，事实先行**：开头第一句直接阐明系统输入、物理边界与核心技术目标。
- **主谓宾清晰，动宾搭配专业**：例如使用“计算矩阵条件数”、“执行马氏距离门控加权”、“更新离散状态协方差”、“触发单次原子授权”，杜绝口语化或含混不清的表述。
- **严谨界定因果链**：每项技术指标必须有对应的数据流与算法支撑。技术优势必须由“通过某种明确的结构特征或数据变换，解决了某种客观物理/数值约束”自然推导得出。

## 二、 事实驱动：三层技术边界划分

在任何技术方案与工程规范撰写中，绝不能把“未实现的设想”伪造成“已实施的系统”。必须严格将技术内容解耦为三个层级：

### 1. 第一层：工程代码已存在的客观事实
- **定义**：当前工程代码库中已经稳定运行、具备完整函数实现的模块与算法链路。
- **写作要求**：直截了当按实际运行链路撰写。明确实际使用的数据结构、接口定义、参数配置与调用逻辑，不人为添加不存在的复杂度。

### 2. 第二层：现有模块组合派生的系统架构方案
- **定义**：由既有代码中的独立模块、状态机、事件流与算法单元，经过系统级拓扑编排而形成的一体化方案。
- **写作要求**：重点交代各模块之间的时序配合、同步机制与数据契约。交代清楚各子系统之间如何通过特定事件或状态凭据实现端到端闭环。

### 3. 第三层：待实机确认的增强实施例
- **定义**：算法设计在理论上完备，但工程实现中目前作为预留分支、参数未完全标定或依赖特定硬件回执的特征。
- **写作要求**：
  - 必须明确使用“在另一可选实施例中”、“进一步优选地”进行规范引出；
  - 明确指出该增强方案依赖的外部条件（如特定传感器外参标定、在线延迟统计回执等）；
  - **严禁将未完成闭环的设想冒充为默认主流程**。

## 三、 技术步骤的六要素闭环模型

文档中凡涉及核心算法、执行步骤或业务流转逻辑（如 S1, S2, ..., Sn），必须完整覆盖以下六个维度，形成不可分割的逻辑闭环：

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. 输入与前置依赖 (Input & Dependency)                     │
│    来源模块、变量名、数据结构、量纲单位                      │
├─────────────────────────────────────────────────────────────┤
│ 2. 处理过程与基准参考 (Processing & Reference Frames)       │
│    计算逻辑、变换矩阵、所在物理坐标系                        │
├─────────────────────────────────────────────────────────────┤
│ 3. 公式推导与参数即刻解释 (Formula & Immediate Explanation) │
│    数学表达式 + 正下方逐一解释所有符号与物理意义              │
├─────────────────────────────────────────────────────────────┤
│ 4. 阈值与判定分支 (Threshold & Conditional Decision)        │
│    数学判决不等式、物理极限或标定依据                        │
├─────────────────────────────────────────────────────────────┤
│ 5. 输出与数据流向 (Output & Data Flow)                      │
│    输出变量、状态锁存、代际凭证 generation、下游接收方      │
├─────────────────────────────────────────────────────────────┤
│ 6. 异常分支与回路 (Exception & Fallback Loop)               │
│    超时/奇异值/越界/缺失时的保持、重试或安全降级策略         │
└─────────────────────────────────────────────────────────────┘
```

### 通用抽象范例：
> **步骤 S3：基于反馈时延与运动外推的执行状态预测**
> 
> - **输入**：从执行机构传感器接口获取当前广义坐标反馈 $\mathbf{q}_{\mathrm{fb}}$、广义速度反馈 $\dot{\mathbf{q}}_{\mathrm{fb}}$，以及采样硬件时间戳 $t_{\mathrm{stamp}}$；从主控制器时钟获取当前调度周期基准时刻 $t_{\mathrm{now}}$。
> - **处理过程**：首先计算反馈数据的滞后时间差 $\tau_{\mathrm{lag}} = t_{\mathrm{now}} - t_{\mathrm{stamp}}$；当滞后时间差处于允许时间窗口内时，在系统基准坐标系下沿运动切线方向执行状态外推，预测执行机构在目标控制时刻的状态分布。
> - **公式计算**：
>   \[
>   \mathbf{q}_{\mathrm{pred}}(t) = \mathbf{q}_{\mathrm{fb}} + \dot{\mathbf{q}}_{\mathrm{fb}}\cdot(t - t_{\mathrm{stamp}}) + \frac{1}{2}\hat{\mathbf{a}}_{\mathrm{est}}\cdot(t - t_{\mathrm{stamp}})^2
>   \]
>   其中，$\mathbf{q}_{\mathrm{pred}}(t)$ 是预测在未来控制时刻 $t$ 的执行机构广义位置向量；$\mathbf{q}_{\mathrm{fb}}$ 是当前采样周期接收到的实际位置反馈向量；$\dot{\mathbf{q}}_{\mathrm{fb}}$ 是当前广义速度向量；$\hat{\mathbf{a}}_{\mathrm{est}}$ 是通过历史多周期速度差分估计的等效加速度向量；$t_{\mathrm{stamp}}$ 是传感器端硬件采样时间戳；$(t - t_{\mathrm{stamp}})$ 为从数据采集至目标动作生效时刻的累计时延。
> - **判定分支**：
>   若滞后时间差 $\tau_{\mathrm{lag}} > \tau_{\max}$（其中 $\tau_{\max}$ 为预设的通信超时上限阈值），或检测到时间戳倒退 $t_{\mathrm{now}} < t_{\mathrm{stamp}}$，判定当前数据失效，跳转至异常处理分支；否则判定数据有效，继续计算目标到达时刻 $t_{\mathrm{target}}$。
> - **输出**：输出预测状态向量 $\mathbf{q}_{\mathrm{pred}}$ 与状态置信度评估值 $C_{\mathrm{state}}$，传递给步骤 S4 供联合决策门控使用。
> - **异常处理回路**：若判定当前数据失效，系统保持当前安全输出，记录传感器异常诊断日志，并向主监控模块上报超时告警，安全终止本次前馈预测流程。

## 四、 公式与参数的极严准则（全文档通用）

1. **参数即刻解释铁律**：
   - 任何公式出现后，**必须在公式正下方第一段立即完成对所有涉及参数的逐一解释**。
   - 解释格式应采用：“其中，$\alpha$ 为…，其物理含义是…；$\beta$ 为…，用于表征…”。
   - 绝不允许将参数解释推迟到后续章节或整个小节末尾，更不能漏掉中间变量。
2. **符号全局唯一性**：
   - 全文同一变量符号只能表达同一个物理量。
   - 若存在相近概念，必须使用角标明确区分（例如：状态协方差矩阵使用 $\mathbf{\Sigma}$，加权矩阵使用 $\mathbf{W}$，测量噪声协方差使用 $\mathbf{R}$；主运动雅可比矩阵使用 $\mathbf{J}_{\mathrm{main}}$，全维度雅可比使用 $\mathbf{J}$）。
   - 避免使用单个多义字符指代不同对象（如字母 $p$ 既表示阶数指数又表示空间坐标向量，易造成歧义；指数应使用 $\gamma$ 或 $k$）。

## 五、 数值实施例规范

无论是在 Markdown 设计文档、Word 方案报告还是 Wiki 规范中，均应包含至少一组完整的、由合理物理参数驱动的通用数值实施例：
- **参数来源真实合理**：明确物理极限约束（如广义坐标位移限位、最大允许角速度、最大允许加速度）、传感器测量频率（如 $500\text{ Hz}$，对应采样周期 $2\text{ ms}$）、典型硬件通信滞后量级等。
- **可复算性**：评审人员或工程同行将这套数值代入公式中，能够逐步算出各阶段的中间结果与最终输出，保证方案充分公开、具备高度的可实施性与工程说服力。
