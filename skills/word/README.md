# 通用技术文档撰写技能 (`word`)

本技能确立了一套普适于**所有文档类工作**（系统架构方案、工程技术规范、算法设计说明、接口契约文档、技术白皮书、工程复盘总结等）的高水准文字口吻、叙事手法与工程注意事项。

无论最终载体是 Word (`.docx`)、Markdown (`.md`)、PDF、在线 Wiki 还是代码库内的设计说明，均通用遵循本技能的行文准则。

## 技能定位

- **普适工程写作准则**：聚焦于文字口吻、叙事手法与注意事项，彻底摆脱形式化八股与特定文件格式束缚。
- **客观沉稳的工程师口吻**：开门见山、事实先行，严禁复述需求，杜绝一切 AI 套话与浮夸口号。
- **基于约束与权衡的叙事手法**：从实际矛盾出发，层层递进推导方案因果链路，虚实分明地展现工程边界。
- **严密自洽的数学表达**：公式出现后正下方即时交代变量定义与物理工程含义，保持符号全局唯一，结合真实量纲可推演复算。
- **全面的系统兜底意识**：不仅阐述理想链路，更深入剖析边界约束、异常防御与安全降级策略。
- **全维度脱敏解耦**：采用通用工程学与控制理论抽象表达，不涉及任何私有商业实体与特定机型。
- **标准工程技术报告排版系统（全文档默认基准）**：所有 Word (`.docx`) 及正式工程文档产出，**若无特殊要求，均默认且强制采用此套排版规范**（标准 A4、左右 3.17 cm 装订边距、黑体标题梯队、宋体小四号首行缩进 2 字符、单倍行距、0.5 磅细实线表格及居中图表题注），无需每次反复确认。
- **原生矢量排版拓展**：在输出 Word/DOCX 时，基于 OMML 原生矢量公式彻底根除方框乱码与行高突变。
